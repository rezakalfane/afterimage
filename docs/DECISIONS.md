# Decisions and deviations from the kit

> [!WARNING]
> **Spoiler alert:** This engineering log discusses puzzle mechanics, clue locations, and story rules from *AFTERIMAGE*. Play the game first if you want to avoid spoilers!

## Engine changes vs `docs/kit/world-engine.mjs` (canon preserved)
1. **Wrong hiding place**: `preserve_cache` accepts `upper_cabinet | lower_cabinet | desk | floor`. A wrong place returns `WRONG_LOCATION` with the place, which the controller turns into a precise reason and a suggestion. The kit returned `INVALID_ARGUMENT` (kit §4: "refusé avec une raison précise").
2. **Hints per puzzle**: `hintLevels {key, cache, promise}` (three levels each, kit §7 table) plus a total `hintsUsed`. The kit had a single counter capped at 3.
3. **Tool channel**: `request_hint` and `acknowledge_permission` are allowed from the character's tools (the player may ask or agree by voice). `switch_era` and `confirm_message` are UI-only. `choose_ending` is reachable only through `ending-confirmed`, and an `ending-confirmed` context cannot run anything else.
4. **Message normalization**: NFC, CRLF→LF, trim; 1–240 code points; control characters and bidi overrides refused. The stored value is shown back before confirmation.
5. **Preserving twice** is an idempotent no-op instead of a refusal.
6. **The 2026 key is found before the cabinet opens**: new action `find_future_key` (2026, requires `cache_preserved`, sets `future_key_found`, the key is behind the projector). `recover_cache` now requires `future_key_found`. In playtests Malik opened the cabinet without any key, which broke the symmetry with Jeanne's G7 puzzle. Malik's tool `malik_act` takes `geste: chercher_cle | ouvrir_armoire` (en `gesture: look_for_key | open_cabinet`).

## Kit inconsistencies fixed
- `characters.json` → Jeanne `initialKnown` contained "elle ignore qu'elle est sous G7", which leaked G7 into Jeanne's context and contradicted her `unknown` list ("G7 avant transmission"). It now reads "Elle a égaré la clé et ignore où elle se trouve."
- Schema: `invitations.role` also allows `owner`, only for the CLI bootstrap invitation (the kit forbids a public `/setup` route). Added `ending_intents` (single-use confirmation tokens). Leases carry `user_id` and `external_client_id` for ownership checks and reconciliation.

## Architecture choices
- **Mutations use raw parameterized SQL in `client.transaction("write")`**, because Drizzle's libSQL transaction ignores the mode. Drizzle is used for the schema, migrations and Better Auth.
- **Implicit tools only.** The browser relays tool calls to `/api/runs/:id/tool` and the server re-validates everything. Not used: WebSocket tool servers (`ui_update`, `context_update`), because they need a public `wss://` endpoint (kit §11).
- **Context injection**: `externalClientProfile` at connection time. After a UI mutation while live, the browser sends a `send_message` with `role: system` carrying the new projection (documented commands). Tool outputs carry it too. Tested live: Jeanne reacts to a clue relayed from the UI.
- **Agents**: the 4 existing agents are reused and none is created. `fr` = P0 for every environment, `en` = P1. Environment isolation comes from the memory identity HMAC and separate databases.
- **Capacity**: DB leases plus one shared rate slot (1.5 s, because Napster counts request arrivals) for create and delete. One safe retry on 429 (not created). Expired leases count as `uncertain` until reconciled. When capacity looks full, the open route reconciles once before refusing.
- **SDK 2.0.0** differs from the online docs (token function, `layout`/`style` objects, SDK-managed mic prompt). The code follows the installed `.d.ts`.
- **E2E on a production build**: cold dev compiles crashed or timed out the headless browser.
- **Tool outputs state the next usable tools** (`outilsMaintenant`): live runs showed the model repeating a no-op tool and then concluding it could not act.
- **Migration 0001 is hand-written** (`ALTER TABLE … ADD COLUMN`): drizzle-kit generated a table rebuild that selected the not-yet-existing column.
- **Fonts**: Cormorant Garamond and Source Sans 3 via `next/font`, downloaded at build and self-hosted (SIL OFL 1.1).

- **Own leases are taken over**: opening a conversation closes the caller's previous open lease on the same run (reload, language switch during an open, second tab), and a UI era switch closes the previous era's conversation before switching. Napster is called outside the transaction; the newest request wins and there is still one avatar per run. Before this, a lease left by a reload during an open locked the run (no talk, no era switch) until reconciliation.
- **Server error messages** are thrown in French (reference) and translated by the route handler from `src/server/security/error-texts.ts`; a unit test fails if a thrown French message has no English entry.

- **Voice play** (user request "play the whole game with voice", principle validated by the user for the message and the final choice, as a complement to the button): the confirmation rule is kept in substance. Final pass hardening: only FINAL user transcripts (not typed text, never the character); the whole utterance must be an explicit affirmative phrase (anchored; questions, negations, hesitation, hypotheses and reported speech refused; a bare "oui" does not count); the confirmation is bound to a target (kind, exact text or ending, server revision, live session) created when the step is shown — any change, a closed panel or a new session invalidates it; earlier, repeated (same item id) or out-of-step events are ignored; single use. An ending is only *selected* by an explicit "je choisis …" and still needs its own confirmation. `?voicedebug=1` shows heard text → decision for the acceptance test. While the message sheet is in review, or an ending is selected, an explicit confirmation in the player's OWN words (speech transcript or typed text; `src/components/game/voice.ts`, negations refused) makes the browser send the same UI command as the button (`confirm_message`, then `/ending` with the single-use token). The model never confirms and has no tool for it. The sheet opens when Jeanne notes a draft; the choice opens itself in live mode once the decision is possible; windows close ~2 s after a validated gesture (readings stay open).
- **Closing the cabinet** (user request "allow more freedom"): `close_cabinet` sets `door_closed_<era>`; opening again (`open_cabinet` 1996, `recover_cache` 2026) only reopens the door. Reading inside and storing need the door open (`PREREQUISITE_MISSING`, detail `door`). No canon or prerequisite change. Tools: `geste/gesture = fermer_armoire/close_cabinet`.
- **Full-window scene with a PiP companion** (concept "fullscreen PiP"): from 901×520 the booth covers the window (cover sized from the stage container, hotspots stay on the image); the companion is a compact, draggable tile (default lower left, clear of the hotspots, position remembered); notebook in the bottom bar; centred subtitles; era change cross-fades the scenes.
- **Tool argument tolerance**: JSON-string arguments are parsed, and a location given with a gesture other than "store" is ignored; everything is still validated. Rejected calls are logged with an explicit allow-list only (`rejectedToolLog`: character, known tool name, refusal code, revision, call id) — never arguments, which may carry the personal sentence.
- **Objective worded for the era on screen**: after storing / when deciding, 1996 says "Retournez en 2026 …"; in 2026 the promise step is placed "En 1996 …"; phases whose clues span both eras stay neutral.

- **Chapter v2 (brief v3)**: content versioned (`episode.json` version 2, a new `episode_versions` row). Runs of v1 are retired: kept and readable, refused on every mutation path (commands, tools, ending, rehearsal, conversation), outside the quota, and not offered as "Reprendre". Rationale: two engines in parallel would cost more than the brief needs.
- **Player-backed shares**: the browser posts each FINAL player transcript and typed line to `/api/runs/:id/turn`; the server stores only a hash, booleans (note, water, report, future), a parsed seat and place (`player_turns`). A character's tool call that records a share needs such a turn in the same lease within 2 minutes. Limit: it proves the player's own client reported that turn, not a cryptographic truth. When the model skips a share that the player's turn backs (e.g. asks the row before sharing the note, or searches before proposing the seat), the server records the backed share first.
- **No spoiler in global agent configuration**: seat and storage place are free-text arguments; the tool definitions, prompts and provisioning appendix contain no G7, row, seat number or hiding place (checked live on the account). Version data reaches the model only through the connection profile and tool outputs.

## Known gaps (not hidden)
- **Multilingual**: French and English are both active. UI strings live in `src/i18n/messages.ts`; the episode's English content is in `src/content/episodes/last-screening/v1/i18n.en.ts`; server texts, prompts, tools and rehearsal replies are keyed by locale. The player picks the language in Settings (home) or with the FR|EN switch (top bar); the choice is a cookie and the page reloads; the run state is language-free, so the game continues where it was. Leases store the session locale, so a live session keeps its agent's language. Still French only: the admin and privacy pages. The English texts need a native review.
- The `en` prompts are my translation of the kit and need a native review.
- CSP is report-only until the Napster media/signalling domains are observed on staging (kit §18.9).
- Turso Cloud (`afterimage-db`, Vercel Marketplace) is live in production (`https://afterimage-vert.vercel.app`) with migrations, owner bootstrap and live smoke tests verified; high-concurrency tests, backups and restore rehearsals remain to be run.
